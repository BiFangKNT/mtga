## 引言
本文档系统阐述MTGA项目的发布前质量保障流程，涵盖多平台构建验证、可执行文件签名状态检查、反病毒扫描集成、SHA256校验和生成与验证等关键环节。文档结合`build_mac_app.sh`和`build_onefile.bat`构建脚本，详细说明不同平台下构建产物的命名规范及其平台标识规则，并提供完整的发布清单（release checklist），确保发布过程的完整性与安全性。

## 多平台构建验证

### Windows平台构建验证
Windows平台使用`build_onefile.bat`脚本进行单文件构建，该脚本通过Nuitka将整个应用程序打包为一个独立的`.exe`文件。构建过程包括以下关键步骤：

1. **环境检查**：脚本首先检查虚拟环境（`.venv\Scripts\python.exe`）是否存在，确保依赖已正确安装。
2. **编译器检查**：验证Visual Studio 2022的MSVC工具链是否可用，这是Windows平台编译的必要条件。
3. **版本注入**：将版本号写入`modules\runtime\_build_version.py`文件，供运行时读取。
4. **Nuitka构建**：使用`uv run`命令调用Nuitka执行单文件编译，包含所有必要的资源文件和依赖。
5. **输出验证**：构建完成后，脚本验证输出文件`dist-onefile\MTGA_GUI-v{版本号}-x64.exe`是否存在。

构建成功后，输出文件具有以下特点：
- 仅一个`.exe`文件，便于分发
- 启动时自动解压到临时目录
- 包含所有依赖，无需额外文件
- 自动请求管理员权限

### macOS平台构建验证
macOS平台使用`build_mac_app.sh`脚本创建标准的`.app`应用程序包。构建过程包括以下关键步骤：

1. **环境检查**：验证虚拟环境、clang编译器和Nuitka是否已正确安装。
2. **版本注入**：将版本号写入`modules/runtime/_build_version.py`文件。
3. **应用包创建**：使用`uv run`调用Nuitka创建独立的应用程序包，包含所有依赖。
4. **Bundle ID修复**：如果`Info.plist`中的`CFBundleIdentifier`为无效格式，脚本会自动修复为`com.mtga.gui`。
5. **DMG创建**：可选地使用`dmgbuild`工具创建专业的DMG安装包。

构建成功后，应用程序包具有以下特点：
- 标准macOS `.app`应用程序包格式
- 独立运行，包含所有依赖
- 启动速度快，无需解压
- 可直接拖拽到Applications文件夹
- 支持Spotlight搜索和系统集成

此外，项目提供了`mac/create_mac_app.sh`脚本用于创建应用程序包结构，以及`mac/dmg_settings.py`配置文件用于定义DMG的外观和布局。

## 可执行文件签名与反病毒扫描

### 可执行文件签名状态
根据项目构建脚本和文档分析，当前发布流程中可执行文件的签名状态如下：

- **Windows平台**：`build_onefile.bat`脚本未集成代码签名功能。生成的`.exe`文件为未签名状态，这可能导致杀毒软件误报或用户在首次运行时遇到安全警告。
- **macOS平台**：`build_mac_app.sh`脚本未集成Apple代码签名（`codesign`）和公证（`notarization`）流程。生成的`.app`文件为未签名状态，用户在首次运行时可能需要通过系统偏好设置手动允许运行。

建议在未来的发布流程中集成代码签名机制，以提高用户信任度并减少安全警告。

### 反病毒扫描集成
项目文档中未提及自动化的反病毒扫描集成。然而，`Windows_Onefile_Build.md`文档明确指出：
> "杀毒软件可能误报（属正常现象）"

这表明项目团队已意识到单文件可执行文件可能被杀毒软件误报为恶意软件。建议在发布流程中增加以下反病毒扫描步骤：
1. 使用多个主流杀毒软件（如Windows Defender、Kaspersky、Bitdefender等）对构建产物进行扫描
2. 将构建产物提交到VirusTotal等在线扫描服务进行多引擎检测
3. 记录扫描结果并作为发布清单的一部分

## SHA256校验和生成与验证

### 校验和生成
为确保发布包的完整性与安全性，必须生成并提供SHA256校验和。虽然项目当前的构建脚本未自动生SHA256校验和，但可以使用标准工具手动生成：

**Windows平台**：
```cmd
certutil -hashfile MTGA_GUI-v1.2.0-x64.exe SHA256
```

**macOS平台**：
```bash
shasum -a 256 MTGA_GUI-v1.2.0-arm64.dmg
```

建议将校验和生成步骤集成到构建脚本中，例如在`build_onefile.bat`和`build_mac_app.sh`的末尾添加相应的命令，并将输出重定向到`sha256sum.txt`文件。

### 校验和验证
用户在下载发布包后应验证其SHA256校验和，以确保文件未被篡改或损坏。验证方法如下：

**Windows平台**：
```cmd
certutil -hashfile MTGA_GUI-v1.2.0-x64.exe SHA256
```
将输出的哈希值与官方发布的校验和进行比对。

**macOS平台**：
```bash
shasum -a 256 MTGA_GUI-v1.2.0-arm64.dmg
```
将输出的哈希值与官方发布的校验和进行比对。

建议在发布说明中提供详细的校验和验证指南，帮助用户完成验证过程。

## 构建产物命名规范

### 命名规则
项目在不同平台下的构建产物遵循明确的命名规范，确保版本识别和平台区分的清晰性。

**Windows平台**：
- 格式：`MTGA_GUI-v{版本号}-x64.exe`
- 示例：`MTGA_GUI-v1.2.0-x64.exe`
- 平台标识：`x64`表示64位Windows平台

**macOS平台**：
- 格式：`MTGA_GUI-v{版本号}-{架构}.dmg`
- 示例：`MTGA_GUI-v1.2.0-arm64.dmg`
- 平台标识：`arm64`表示Apple Silicon架构，`x64`表示Intel架构

### 平台标识规则
平台标识符遵循以下规则：
- `x64`：用于64位Windows和Intel架构的macOS
- `arm64`：用于Apple Silicon架构的macOS

这些命名规范在`build_onefile.bat`和`build_mac_app.sh`脚本中通过`--output-filename`参数实现，确保构建产物的名称与版本号和平台架构保持一致。
