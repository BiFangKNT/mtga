## 错误码对照表

根据 `modules/runtime/error_codes.py` 文件定义，系统使用 `ErrorCode` 枚举类来标准化错误处理。以下是完整的错误码对照表，包含每个错误的含义、可能原因和解决方案。

| 错误码 | 中文描述 | 可能原因 | 解决方案 |
|--------|----------|----------|----------|
| UNKNOWN | 发生未知错误 | 未预期的异常或内部错误 | 检查日志文件获取详细堆栈信息，重启应用，若问题持续请报告开发者 |
| CONFIG_INVALID | 配置无效 | 全局配置缺失或字段为空 | 检查“映射模型ID”和“MTGA鉴权Key”是否已正确填写 |
| NETWORK_ERROR | 网络异常 | 无法连接到目标服务器或网络中断 | 检查本地网络连接，确认目标API地址可达，关闭可能的防火墙或代理干扰 |
| REMOTE_ERROR | 远程服务异常 | 目标API返回错误状态码（如4xx/5xx） | 检查API密钥是否有效，确认目标服务状态正常 |
| NO_VERSION | 未解析到版本号 | 无法从响应中获取版本信息 | 检查网络连接和API端点是否正确 |
| FILE_NOT_FOUND | 文件不存在 | 指定的文件路径无效或文件被删除 | 确认文件路径正确，必要时重新生成或恢复备份 |
| PERMISSION_DENIED | 权限不足 | 程序无权访问或修改特定文件 | **Windows**: 以管理员身份运行程序<br>**macOS**: 授予程序管理员权限<br>检查安全软件是否阻止访问 |
| PORT_IN_USE | 端口已被占用 | 指定的代理端口（如443）正被其他进程使用 | 使用 `netstat` 或任务管理器查找占用端口的进程并结束，或更改代理端口配置 |
| BACKUP_DIR_MISSING | 未找到备份文件夹 | 备份目录不存在 | 程序会自动创建用户数据目录，通常无需手动干预 |
| NO_BACKUPS | 未找到任何备份 | 尚未执行过hosts文件备份操作 | 执行一次“备份hosts文件”操作以创建初始备份 |

## 系统级检查清单

在启动代理服务前，必须完成以下系统级检查，以确保环境配置正确。

### 1. 证书是否正确安装并受信任

- **检查方法**:
  - 程序日志中应显示 `✅ CA证书安装完成`。
  - 在操作系统证书管理器中搜索 CA 证书的通用名称（如 `api.openai.com`）。
- **常见问题**:
  - **CERT_INSTALL_FAILED**: 证书安装失败。可能原因包括找不到证书文件或安装过程被中断。
  - **解决方案**: 确认 `ca` 目录下存在 `rootCA.crt` 文件，然后重新执行“生成证书”和“安装CA证书”操作。

### 2. Hosts文件是否包含正确条目

- **检查方法**:
  - 打开 `C:\Windows\System32\drivers\etc\hosts` (Windows) 或 `/etc/hosts` (macOS/Linux)。
  - 检查文件末尾是否包含类似 `127.0.0.1 api.openai.com` 的条目。
- **常见问题**:
  - **HOSTS_WRITE_PERMISSION_DENIED**: 写入hosts文件权限被拒绝。
  - **解决方案**: 以管理员身份运行程序。如果已是管理员，检查hosts文件是否被安全软件或系统设置设为只读。

### 3. 指定端口是否被占用

- **检查方法**:
  - 程序在启动代理前会自动检查端口443是否被占用。
  - 手动检查命令:
    - **Windows**: `netstat -ano | findstr :443`
    - **macOS/Linux**: `lsof -i :443`
- **常见问题**:
  - **PROXY_PORT_IN_USE**: 代理端口被占用。
  - **解决方案**: 结束占用端口的进程（如IIS、其他代理软件），或修改代理配置使用其他端口。

### 4. 防火墙是否阻止连接

- **检查方法**:
  - 尝试从浏览器访问 `https://api.openai.com`。
  - 如果无法访问，检查系统防火墙或第三方安全软件设置。
- **解决方案**:
  - 将本程序添加到防火墙白名单。
  - 临时关闭防火墙进行测试，以确认是否为防火墙导致的问题。

## 目标API连通性测试

使用 `test_target_api.py` 脚本可以独立验证目标API的可达性，排除代理层干扰。

### 使用步骤

1. 编辑 `test_target_api.py` 文件，配置以下参数：
   ```python
   TARGET_API_BASE_URL = "https://api.openai.com"  # 目标API地址
   API_KEY = "sk-你的实际密钥"                    # 你的API密钥
   MODEL_ID = "gpt-3.5-turbo"                     # 要测试的模型ID
   ```
2. 运行脚本：
   ```bash
   python test_target_api.py
   ```
3. 观察输出结果。

### 预期输出

- **成功**:
  ```
  状态码: 200
  响应体: {"id": "...", "object": "chat.completion", ...}
  ```
- **失败**:
  - `NETWORK_ERROR`: 检查网络连接和 `TARGET_API_BASE_URL` 是否正确。
  - `REMOTE_ERROR`: 检查 `API_KEY` 是否有效，或目标服务是否宕机。

此测试直接与目标API通信，如果测试失败，则问题出在本地网络或API密钥本身，而非代理配置。

## 日志查看与问题定位

程序的日志是诊断问题的关键。

### 日志文件位置

- 日志文件存储在用户数据目录中，通常位于：
  - **Windows**: `C:\Users\<用户名>\AppData\Roaming\ModelRelay\`
  - **macOS**: `~/Library/Application Support/ModelRelay/`
- 主要日志文件为 `error.log`，记录所有ERROR级别信息。

### 日志分析技巧

- **搜索关键词**:
  - `❌`: 表示操作失败，紧随其后的消息是错误原因。
  - `⚠️`: 表示警告，可能影响功能但未导致失败。
  - `端口已被占用`: 明确指示 `PORT_IN_USE` 错误。
  - `权限不足`: 明确指示 `PERMISSION_DENIED` 错误。
- **关联操作**:
  - 如果“一键启动”失败，按顺序检查日志中“生成证书”、“安装CA证书”、“修改hosts文件”、“启动代理服务器”各步骤的输出，定位第一个失败环节。

## 恢复操作指南

当配置出现问题时，可执行以下恢复操作。

### 1. 证书清理

- **目的**: 移除已安装的CA证书，解决证书冲突或信任问题。
- **操作**:
  - 在程序界面点击“清除CA证书”。
  - 或调用 `cert_service.clear_ca_cert_result()`。
- **验证**: 检查操作系统证书存储，确认相关证书已被移除。

### 2. 代理重启

- **目的**: 应用新的配置或从错误状态恢复。
- **操作**:
  - 在程序界面点击“停止代理”，然后点击“启动代理”。
  - 或调用 `proxy_orchestration.restart_proxy()`。
- **注意**: 重启前确保配置已保存。

### 3. 配置重置

- **目的**: 恢复到默认状态。
- **操作**:
  1. 停止代理。
  2. 清除CA证书。
  3. 还原hosts文件（使用备份）。
  4. 重新生成并安装证书。
  5. 重新修改hosts文件。
  6. 启动代理。

此流程可解决绝大多数由配置错误引起的故障。

## 高级调试技巧

### 网络抓包建议

- **工具**: 使用 Wireshark 或 Fiddler。
- **目的**: 分析代理服务器与目标API之间的实际通信。
- **步骤**:
  1. 启动抓包工具并开始捕获。
  2. 执行一个通过代理的API调用。
  3. 停止捕获，过滤 `TLS` 或 `HTTPS` 流量。
  4. 检查是否有 `Client Hello` 发往 `api.openai.com`，确认流量被正确重定向。

### 浏览器证书验证技巧

- **目的**: 确认浏览器信任代理的CA证书。
- **步骤**:
  1. 在浏览器中访问 `https://api.openai.com`。
  2. 点击地址栏的锁形图标。
  3. 查看证书信息。
  4. 在证书路径中，应能看到由本程序生成的CA证书作为根证书。
- **问题**: 如果只看到OpenAI的原始证书，则说明代理的证书未被信任，需要重新安装CA证书。
