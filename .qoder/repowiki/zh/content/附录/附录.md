## 预置服务商证书配置模板

- **配置文件**: `ca/api.openai.com.cnf`
- **域名**: `api.openai.com`
- **配置内容**:
  ```ini
  [ alt_names ]
  DNS.1 = api.openai.com
  ```

## .cnf文件字段含义与生成规则

### .cnf 文件核心字段解释

`.cnf` 文件是 OpenSSL 的配置文件，用于定义证书的生成规则和扩展属性。以下是项目中使用的关键字段及其含义：

#### v3_req.cnf
此文件定义了服务器证书（非CA）的通用扩展属性。
- **[ v3_req ]**: 配置段标识。
- **basicConstraints = CA:FALSE**: 表明此证书不是证书颁发机构（CA），不能用于签发其他证书。
- **keyUsage**: 定义了公钥的用途。
  - `nonRepudiation`: 不可否认性
  - `digitalSignature`: 数字签名
  - `keyEncipherment`: 密钥加密
- **subjectAltName = @alt_names**: 指定主题备用名称（SAN）的来源，引用 `alt_names` 段。

#### v3_ca.cnf
此文件定义了CA证书的扩展属性。
- **[ v3_ca ]**: 配置段标识。
- **subjectKeyIdentifier=hash**: 使用公钥的哈希值作为主题密钥标识符。
- **authorityKeyIdentifier=keyid:always,issuer**: 指定权威密钥标识符，包含CA的密钥ID和颁发者信息。
- **basicConstraints = critical, CA:TRUE, pathlen:3**: 关键约束，表明此证书是CA证书，并且最多可以签发3级下级CA。
- **keyUsage = critical, cRLSign, keyCertSign**: 关键用途，用于证书吊销列表（CRL）签名和证书签名。
- **nsCertType = sslCA, emailCA**: Netscape证书类型，表示可用于SSL和电子邮件的CA。

#### 服务商特定 .cnf 文件 (如 api.openai.com.cnf)
这些文件主要定义了 `alt_names` 段，用于指定证书所覆盖的域名。
- **[ alt_names ]**: 主题备用名称段。
- **DNS.1, DNS.2, ...**: 列出所有需要包含在证书中的域名。使用通配符 `*` 可以匹配子域名。

### 证书生成规则

项目提供了多种方式来生成证书，核心规则如下：

1.  **CA证书生成** (`genca.sh` 或 `generate_certs.py`):
    - 使用 `openssl genrsa` 生成2048位的RSA私钥 (`ca.key`)。
    - 使用 `openssl req -x509` 生成自签名的CA证书 (`ca.crt`)，有效期为100年（36500天）。
    - 证书信息（如CN、O、OU）在脚本中预设，无需用户交互。

2.  **服务器证书生成** (`gencrt.sh` 或 `generate_certs.py`):
    - 使用 `openssl genrsa` 生成2048位的RSA私钥（如 `api.openai.com.key`）。
    - 将私钥转换为PKCS#8格式以提高兼容性。
    - 使用 `openssl req` 生成证书签名请求（CSR）。
    - 使用 `openssl x509` 和CA的私钥 (`ca.key`) 签署CSR，生成最终的服务器证书（如 `api.openai.com.crt`），有效期为1年（365天）。
    - 服务器证书的 `Subject` 信息从 `.subj` 文件读取，`Subject Alternative Name` 从 `.cnf` 文件读取。

## 安全注意事项

### 私钥保护
- **CA私钥 (`ca.key`)**: 这是最关键的机密文件。一旦泄露，攻击者可以签发任意域名的可信证书，进行中间人攻击。必须严格保护，切勿上传至代码仓库或与他人分享。
- **服务器私钥**: 虽然重要性低于CA私钥，但也应妥善保管，防止被未授权访问。

### 证书有效期管理
- **CA证书**: 项目中生成的CA证书有效期为100年。虽然方便，但不符合最佳安全实践。建议在生产环境中使用较短的有效期（如5-10年）。
- **服务器证书**: 有效期为1年。当证书过期后，HTTPS连接将失败。需要定期重新生成服务器证书。

### 证书轮换
- **定期轮换**: 为了降低私钥泄露带来的长期风险，建议定期（例如每年）轮换CA证书和服务器证书。
- **轮换流程**: 轮换CA证书时，需要重新生成所有服务器证书，并将新的CA证书重新导入到所有客户端的受信任根证书存储中。

## 平台特定附加说明

### Windows 单文件构建指南
本指南详细说明了如何使用 Nuitka 将项目打包为一个独立的 `.exe` 文件，这是推荐的发行方式。

- **优点**: 仅一个可执行文件，便于分发和部署。
- **环境要求**: Visual Studio 2022 (C++构建工具)、Python 3.13、uv 包管理器。
- **构建步骤**: 运行 `build_onefile.bat` 脚本。
- **用户数据**: 单文件版本使用 `%APPDATA%\MTGA\` 目录进行用户数据持久化存储，包含配置文件、证书和备份。
- **调试**: 构建过程耗时较长（30-40分钟），首次运行因需解压而较慢。

**节来源**
- [Windows_Onefile_Build.md](file://docs/Windows_Onefile_Build.md)

### DMG 镜像制作细节
本指南说明了如何为 macOS 创建专业的安装包（DMG 文件）。

- **核心脚本**: `mac/create_mac_app.sh` 用于创建 `.app` 应用程序包，`uv run dmgbuild` 用于创建DMG。
- **构建步骤**:
  1.  运行 `mac/create_mac_app.sh` 构建应用程序包。
  2.  运行 `uv sync --group mac-build` 安装依赖。
  3.  运行 `uv run dmgbuild -s mac/dmg_settings.py "MTGA GUI Installer" MTGA_GUI-v1.x.x-aarch64.dmg` 创建DMG。
- **特性**: 支持自定义背景图、精确的图标位置控制、拖拽安装指导和现代的UDZO压缩格式。

## 术语表

- **MITM代理 (Man-in-the-Middle Proxy)**: 一种网络代理，位于客户端和服务器之间，能够拦截、查看和修改双方的通信流量。本项目利用MITM代理技术来转发和修改AI API的请求。
- **Subject Alternative Name (SAN)**: X.509证书中的一个扩展字段，允许一个证书为多个域名提供服务。例如，一个证书可以同时保护 `api.openai.com` 和 `*.openai.com`。
- **X.509证书**: 一种广泛使用的公钥证书标准，定义了证书的格式和内容。它包含了公钥、持有者信息、颁发者信息、有效期和数字签名等。
- **CA (Certificate Authority)**: 证书颁发机构，一个受信任的实体，负责签发和管理数字证书。本项目生成一个自签名的本地CA。
- **CSR (Certificate Signing Request)**: 证书签名请求，由证书申请者生成，包含其公钥和身份信息，提交给CA以申请证书。
- **PKCS#8**: 一种用于存储私钥的加密标准格式，比传统的PKCS#1格式更通用和安全。
